# Сборка установщика DARAVE

Цель — чтобы человек без Python скачал один `.exe`, нажал «Далее» и получил
работающую программу. Mixxx для этого **не нужен**: из 25 рабочих модулей
только два обращаются к слою Mixxx, и оба — через `mixxx_controls.py`,
который не импортирует ничего, кроме `dataclasses` и `math`. Сведение,
анализ, рендер и экспорт сета живут целиком внутри DARAVE.

## Одной командой

```powershell
.\build.ps1
```

На выходе: `installer\DARAVE-1.0.0-setup.exe` (≈ 200 МБ).

Ключи:

| Ключ | Что делает |
|---|---|
| `-SkipInstaller` | только `dist\DARAVE` — папку можно запускать как есть |
| `-StemsPack` | вдобавок соберёт пакет слоёв (≈ 2,5 ГБ, 20–30 минут) |
| `-Clean` | пересоздать окружение сборки с нуля |
| `-Version 1.2.0` | номер версии в имени установщика |

## Что нужно на машине сборщика

* **Python 3.12** — именно он. Под 3.13/3.14 ещё нет колёс для части
  зависимостей, и pip уходит собирать их из исходников: либо час, либо
  ошибка компилятора.
* **Inno Setup 6** — `winget install JRSoftware.InnoSetup`, бесплатно.
* Интернет: скачиваются пакеты и ffmpeg.

Пользователю установщика не нужно ничего.

## Две сборки, а не одна

| | Размер | Что внутри |
|---|---|---|
| **Основная** | ≈ 200 МБ | всё: анализ, сведение, рендер, экспорт |
| **Пакет слоёв** | ≈ 2,5 ГБ | torch + demucs, докачивается по кнопке |

Слои нужны примерно одному диджею из трёх — техники на EQ и на фильтре
работают без них. Требовать 3 ГБ скачивания с каждого ради возможности,
которой две трети не воспользуются, не стоит.

Пакет слоёв — это **настоящий переносной Python**, а не файлы внутри exe.
Причина техническая: demucs запускается как `python -m demucs`, а
собранный PyInstaller'ом exe не интерпретатор — `DARAVE.exe -m demucs` не
заработает никогда. Распаковывается в `%LOCALAPPDATA%\DARAVE\stems-python`,
и `stems.py` ищет его там первым делом.

```powershell
.\tools\make_stems_pack.ps1 -Cuda cu124   # cu121 или cpu
```

Скрипт в конце печатает, собран ли torch **с CUDA**. Это не формальность:
с обычного PyPI под Windows приезжает сборка без CUDA, и никакие драйверы
её не оживят — трек считается 20–40 минут вместо 2–4, то есть библиотека
на 48 треков сутки вместо часа.

## Три грабли PyInstaller'а

Все три ломают программу **не при старте**, а через несколько минут — на
первом же разборе трека. Поэтому `build.ps1` после сборки гоняет
`DARAVE.exe --selftest`, который не «импортирует», а реально считает.

1. **`collect_data_files("librosa")`.** librosa читает таблицы фильтров
   файлами из своего пакета. PyInstaller тянет только `.py`.
2. **`collect_all("scipy")`.** Расширения scipy грузятся по имени,
   статический анализ их не видит.
3. **`--onedir`, не `--onefile`.** onefile распаковывает 200 МБ при каждом
   запуске: старт 8–15 секунд вместо одной, и антивирусы к свежераспакованному
   exe куда внимательнее. Плюс DARAVE запускает сам себя подпроцессом — это
   была бы вторая распаковка на каждый скан.

## Запуск самого себя подпроцессом

Скан библиотеки и разделение на слои идут отдельными процессами: на 50
треках это минуты, и в одном процессе браузер всё это время не получал бы
ни прогресса, ни ответа.

Из исходников это `[python, track_analysis.py, ...]`. В сборке
`.py`-файлов рядом нет, и та же строка ломается молча: exe стартует, видит
незнакомый аргумент, поднимает **второй** веб-сервер, тот падает на занятом
порту — а пользователь читает «скан не дал треков».

Поэтому собранный exe умеет работать за скрипт:

```
DARAVE.exe --child track_analysis --scan "C:\Music" --db ...
DARAVE.exe --child stems --dir "C:\Music" --backend demucs --all
```

Список разрешённых модулей закрыт — см. `child.py`.

## Где лежат данные

Программа ставится в папку пользователя, а пишет в
`%LOCALAPPDATA%\DARAVE`: база, логи, наборы, демо, `darave_secrets.json` с
ключами. Разделение не косметическое — в Program Files обычный пользователь
не запишет ни байта, и попытка кончается не понятной ошибкой, а пустым 500
в браузере. См. `paths.py`.

**Удаление программы папку данных не трогает.** Человек сносит программу,
а не полгода своей работы.

## Когда окно мигнуло и закрылось

Первым делом — `--doctor`. Он печатает пять вещей, которыми эта картинка
и отличается одна от другой: свободен ли порт и **кто его держит**, где
папка данных, на месте ли ffmpeg и страница чата, что с ассистентом.

```powershell
C:\DARAVE\DARAVE.exe --doctor
```

Самая частая причина — **порт 8765 уже занят**: обычно это второй
экземпляр или backend, поднятый из исходников. Программа видит занятый
порт, решает, что она уже запущена, и выходит за долю секунды.

Всё, что программа печатает при запуске, дублируется в
`%LOCALAPPDATA%\DARAVE\darave_launch.log` — включая traceback, если она
упала. Окно закрывается, файл остаётся.

## Полезное

```powershell
.\build.ps1 -SkipInstaller       # собрать и проверить, без упаковки
dist\DARAVE\DARAVE.exe --selftest   # 8 проверок на собранном exe
dist\DARAVE\DARAVE.exe --doctor     # почему не запускается
dist\DARAVE\DARAVE.exe --console    # запустить с видимым окном логов
dist\DARAVE\DARAVE.exe --no-browser # не открывать браузер
```

Окно консоли прячется, **только если оно наше** (двойной клик). При
запуске из PowerShell окно общее, и прятать его нельзя: пряталась бы
сессия пользователя вместе с выводом программы.

## Подпись

Без цифровой подписи SmartScreen на первых скачиваниях показывает «Windows
защитила ваш компьютер». Это лечится только сертификатом
(OV ≈ 15 000 ₽/год, EV дороже, но снимает предупреждение сразу). До
подписи имеет смысл написать об этом на странице скачивания — иначе часть
людей просто закроет окно.
