# darave.ru — выложить страницу и установщик

Под ваш хостинг: **REG.RU, ispmanager, Apache + PHP FastCGI 8.3**.
Значит `.htaccess` работает как есть — `nginx.conf.example` вам не нужен,
оставил на случай переезда.

Что в панели уже сделано и трогать не надо: сайт `darave.ru` создан,
корень `/www/darave.ru`, SSL стоит, DNS ведёт на `37.140.192.188`.

Никаких ключей и паролей мне присылать не надо.

## 1. Файлы

`index.html` и `.htaccess` — в `/www/darave.ru/`, установщик — в
`/www/darave.ru/download/`.

173 МБ через «Менеджер файлов» в панели заливать не стоит: там лимит на
загрузку и нет докачки. Берите FTP (FileZilla, WinSCP) — FTP-пользователь
у вас в панели уже заведён, — или Shell-клиент:

```bash
mkdir -p /www/darave.ru/download
```

Точка в начале `.htaccess` — не опечатка. В Менеджере файлов такие файлы
по умолчанию скрыты: включите показ скрытых, иначе будет казаться, что он
не залился. Файл придёт как `htaccess.txt` — переименуйте.

## 2. Проверка

В Shell-клиенте панели или у себя:

```bash
curl -I https://darave.ru/
# ждём: 200, content-type: text/html

curl -I https://darave.ru/download/DARAVE-1.0.0-setup.exe
# ждём: 200, content-length: 181372500, accept-ranges: bytes

curl -sI http://darave.ru/ | head -1
# ждём: 301 (увод на https)
```

`accept-ranges: bytes` — не мелочь. Без него оборванная закачка на 150-м
мегабайте начинается с нуля.

Отдельно проверьте `https://www.darave.ru` — сертификат должен покрывать
оба имени. Редирект с www отрабатывает уже ПОСЛЕ проверки сертификата,
то есть от красного предупреждения браузера не спасает.

Глазами: откройте сайт с телефона.

## 3. Про место и трафик

Раньше я написал, что 173 МБ упрутся в месячный трафик, и **это было
неверно**: у REG.RU на виртуальном хостинге трафик не тарифицируется,
а 15 ГБ — это выделенный объём под базу данных, к файлам сайта он
отношения не имеет.

Ограничение, которое реально есть, — **место на диске**: у тарифов
REG.RU это от 7 до 140 ГБ в зависимости от плана. 173 МБ там теряются,
но каждая новая версия установщика добавляет столько же, так что старые
версии имеет смысл убирать. Свой лимит и текущий расход видно в панели:
левое меню → **«Использование диска»**.

## 4. Что заменить в тексте

Готово: обе кнопки («Купить», «Написать») ведут на `hi@darave.ru`.

Кнопка «Купить» пока открывает письмо. Это честно для старта: платёж не
подключён, и притворяться, что подключён, хуже.

## Чего на сайте намеренно нет

**Подписи кода.** Windows встретит установщик предупреждением
SmartScreen. Об этом прямо написано на странице скачивания вместе с
контрольной суммой — человек, который увидел красное окно без
объяснений, чаще всего просто закрывает браузер. Сертификат (OV
≈ 15 000 ₽/год) снимет это, но до первых продаж покупать его рано.

**Формы и регистрации перед скачиванием.** Почему — см. `LICENSING.md`.


## Как заменить demo.mp4 (и любой файл сайта)

**Одно действие, а не два.** `.github/workflows/deploy.yml` следит за
`site/**` в ветке `main`: пуш → GitHub Actions → `rsync` на reg.ru.
Заливать по FTP руками не нужно.

**Команды — для PowerShell.** Это важно: в PowerShell `copy` это псевдоним
`Copy-Item`, и ключа `/Y` он не знает — отсюда «Не удается найти
позиционный параметр». Нужен `-Force`:

```powershell
cd C:\Users\kam1k88\DARAVE
Copy-Item "C:\Users\kam1k88\Desktop\demo.mp4" "site\demo.mp4" -Force
git add site/demo.mp4
git commit -m "Лендинг: новое демо"
git push
```

Через минуту-две файл на сайте. Ход сборки — вкладка **Actions** в
репозитории; там же кнопка **Run workflow** с галочкой `dry_run`, если
надо посмотреть, что уедет, ничего не трогая.

### Сожмите ролик перед коммитом

Скринкаст с экрана жмётся в разы без потери читаемости текста. Замер на
реальном файле: 1920×1080, 3:10, **59.5 МБ** исходник →

| вариант | размер | текст интерфейса |
|---|---|---|
| 1280×720, CRF 24 | 5.7 МБ | читается |
| **1920×1080, CRF 26** | **7.2 МБ** | **чёткий** |

Разница между ними полтора мегабайта, поэтому для СКРИНКАСТА берём
1080p: там мелкий текст интерфейса, и ради него всё и снимается.

```powershell
ffmpeg -i "исходник.mp4" -c:v libx264 -crf 26 -preset slow `
       -pix_fmt yuv420p -movflags +faststart `
       -c:a aac -b:a 128k "site\demo.mp4"
```

`-movflags +faststart` — не украшение: без него индекс лежит в конце
файла, и браузер не начнёт играть, пока не скачает всё.

### Постер

`demo-poster.jpg` и `.webp` — кадр из ролика, он показывается до нажатия
«play». После замены видео кадр берётся заново:

```powershell
ffmpeg -ss 60 -i "site\demo.mp4" -frames:v 1 -vf scale=1600:-2 -q:v 3 "site\demo-poster.jpg"
ffmpeg -ss 60 -i "site\demo.mp4" -frames:v 1 -vf scale=1600:-2 -c:v libwebp -quality 82 "site\demo-poster.webp"
```

`-ss 60` — секунда, с которой берём кадр. Выбирайте ту, где на экране
что-то говорящее, а не пустая вкладка.

### Три вещи, о которых легко забыть

**1. Подпись про размер.** В `index.html` написано «он на 7 МБ» живым
текстом. Поменялся файл — поменяйте и число, иначе страница врёт.

**2. Кэш браузера.** В `.htaccess` правил для `.mp4` нет, значит сервер
отдаёт свои умолчания, и браузер вправе держать старое видео. Тот, кто
уже был на странице, может увидеть прежний ролик. Лечится именем:

```powershell
git mv site/demo.mp4 site/demo-2.mp4
```

и в `index.html` два места: `<source src="/demo-2.mp4">` и ссылка
«скачайте файл». `rsync --delete` уберёт старый файл с сервера сам. Так
же сделано с установщиком — у него версионное имя и кэш на месяц.

**3. Вес в истории git.** Видео лежит в репозитории, и каждая версия
остаётся в истории НАВСЕГДА — клон тяжелеет на размер каждого ролика.
GitHub предупреждает на файлах больше 50 МБ и отказывает на 100 МБ.
Сжатый ролик на 7 МБ проблемы не создаёт; несжатый на 60 создал бы.

### Что НЕ уезжает на сервер

`rsync` исключает `_config.php` (пароль базы), `*.sql`, `*.log`, `*.md`
и `nginx.conf.example`. То есть эти заметки живут только в репозитории —
и правильно.

### Если Actions недоступны

Запасной путь — FTP (FileZilla/WinSCP) в `/www/darave.ru/`, файл рядом с
`index.html`. Но тогда репозиторий и сайт разойдутся: следующий же пуш
в `site/**` вернёт то, что лежит в git.
