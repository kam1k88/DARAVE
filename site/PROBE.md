# Боевая проверка: 100 ₽ и возврат

Тестовый магазин ЮKassa не умеет СБП, поэтому убедиться, что приём и
возврат денег действительно работают, можно только на живых деньгах.
Сто рублей для этого хватает.

## Что залить

| Файл | Куда |
|---|---|
| `db-refunds.sql` | выполнить в phpMyAdmin поверх базы |
| `api/refund.php` | новый |
| `api/buy.php` | заменить |
| `api/yookassa_webhook.php` | заменить |

`db-refunds.sql` добавляет к заказам состояние `refunded`, номер
возврата и — главное — колонки `tier_before` / `tier_until_before`.
Они нужны, чтобы возврат вернул человека **туда, где он был**, а не
просто в бесплатный тариф.

## 1. Оплатить 100 ₽

Тариф `test` на сайте не показан и закрыт вашим `selftest_secret` —
иначе любой, кто откроет исходник страницы, купит «Полную» за сотню.

Войдите на `https://darave.ru/app/`, откройте консоль браузера (F12) и
выполните:

```js
const r = await fetch('/api/buy.php', {
  method: 'POST', credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ tier: 'test', secret: 'ВАШ_SELFTEST_SECRET' })
});
const d = await r.json();
console.log(d);
if (d.confirmation_url) location.href = d.confirmation_url;
```

Платите по СБП — ради этого всё и затевается.

## 2. Проверить, что засчиталось

```sql
SELECT id, amount, status, payment_id, tier_before, paid_at
  FROM orders ORDER BY id DESC LIMIT 3;
SELECT email, tier, tier_until FROM users;
```

Ждём: заказ `succeeded`, `tier_before = 'free'`, у пользователя
`personal` и `tier_until` через год.

Если заказ завис в `pending` — уведомление не дошло. Смотрите адрес
в кабинете ЮKassa и журнал сайта.

## 3. Вернуть

```powershell
curl.exe -X POST https://darave.ru/api/refund.php `
  -H "Content-Type: application/json" `
  -d '{\"order_id\": 1, \"secret\": \"ВАШ_SELFTEST_SECRET\"}'
```

`order_id` — из запроса выше. В ответе придёт `refund_id`, статус и
новый тариф пользователя.

Проверить:

```sql
SELECT id, status, refund_id, refund_amount, refunded_at FROM orders WHERE id = 1;
SELECT email, tier, tier_until FROM users;
```

Ждём: заказ `refunded`, у пользователя снова `free`.

Частичный возврат — добавьте `"amount": "50.00"`. Тариф при этом
**не понижается**: человек что-то доплатил и что-то вернул, решение за
вами. Суммы складываются: `refund_amount` — это всё возвращённое по
заказу, и вернуть больше оплаченного код не даст, не дожидаясь отказа
ЮKassa.

## Заявка на возврат из кабинета

Тот же возврат, но так, как его увидит покупатель. Проверять надо
обязательно: это единственный путь, по которому деньги уходят **без
вашего участия**.

1. Оплатите тестовые 100 ₽ ещё раз.
2. Зайдите в `/app/` → аватар → «Профиль» → раздел «Оплаты».
3. Нажмите «Вернуть деньги». Оплата свежая, значит попадает в 14 дней:
   подтверждение — и деньги ушли, тариф упал к прежнему, экран
   перерисовался сам.
4. В Telegram должно прийти «Возврат выполнен» с пометкой
   «заявка из кабинета».

Проверить просроченную ветку, не ожидая двух недель:

```sql
UPDATE orders SET paid_at = NOW() - INTERVAL 30 DAY WHERE id = 2;
DELETE FROM refund_requests WHERE order_id = 2;
```

Теперь та же кнопка спросит причину и создаст заявку: деньги не уходят,
приходит уведомление «Заявка на возврат», а заявка появляется в админке
на вкладке «Возвраты» с кнопками «Вернуть» и «Отказать».

## Что проверено заранее

Сами запросы к ЮKassa я проверить не могу — у меня нет ваших ключей и
не должно быть. Проверил всё остальное на живой MariaDB и живом веб-сервере,
с заглушкой вместо ЮKassa — 89 проверок, включая эти:

| Случай | Ответ |
|---|---|
| тариф `test` без секрета | «Неизвестный тариф» |
| возврат без секрета | 404 (постороннему незачем знать, что адрес есть) |
| возврат несуществующего заказа | 404 с номером |
| возврат неоплаченного | 409 «в состоянии pending — возвращать нечего» |
| сумма больше оплаченной | 400 с напоминанием суммы |
| отрицательная сумма | 400 |
| повторный возврат | 409 «уже был возврат» |
| третий возврат после двух частичных | 409 «уже возвращена вся сумма» |
| заявка на чужой заказ | 404 «такой оплаты у вас нет» |
| заявка без входа | 401 |
| вторая заявка по той же оплате | 409 |
| отказ по заявке без пояснения | 400 |
| решение по уже решённой заявке | 409 |
| ЮKassa отказала в возврате по заявке | заявка остаётся ждать, уведомление «Возврат НЕ прошёл» |
| недоплата | тариф не выдан, уведомление «Недоплата» |
| оплата без заказа в базе | 200 (повторы не нужны) + уведомление |
| нет таблицы `refund_requests` | список оплат в кабинете всё равно работает |

Ключ идемпотентности считается от номера заказа и суммы: повторный
вызов вернёт **тот же** возврат, а не сделает второй. Для операции с
деньгами это обязательно — двойной клик стоит денег.

## После проверки

1. Выдать себе чек в «Мой налог» и сделать возвратный чек — возврат
   денег без возвратного чека оставляет доход в декларации.
2. Поставить у заказа `receipt_sent = 1`.
3. Если всё сошлось — `api/selftest.php` можно удалить с сервера.
   `refund.php` оставьте: возврат за 14 дней обещан в оферте, и делать
   его руками в кабинете нельзя — там он не понизит тариф в базе.
