# Куда девать секреты

Вопрос «не знаю, куда их прятать» — правильный, и ответ на него короткий:
**секрет живёт ровно в одном месте на сервере и больше нигде.** Не в
переписке, не в файле на рабочем столе, не в git, не в задаче трекера.

## Срочное: перевыпустить ключ ЮKassa

Секретный ключ, который вы прислали в чат, теперь в истории переписки.
Отозвать содержимое переписки нельзя — можно только сделать ключ
бесполезным.

1. Кабинет ЮKassa → **Интеграция** → **Ключи API**
2. Выпустить новый секретный ключ
3. Старый отозвать
4. Новый вписать сразу в `_config.php` на сервере — как именно, ниже

`shopId` (1464952) секретом не является: это просто номер магазина,
он ездит в каждом запросе. Перевыпускать нужно **только secret_key**.

Чем опасен утёкший ключ: с ним можно создавать платежи от вашего имени,
видеть данные о чужих платежах и **делать возвраты** — то есть уводить
деньги с вашего счёта. Комиссия за такие операции будет ваша.

## Где какой секрет живёт

| Секрет | Единственное место | В git |
|---|---|---|
| Пароль базы | `api/_config.php` на сервере | нет |
| Секретный ключ ЮKassa | `api/_config.php` на сервере | нет |
| Секрет для `selftest.php` | `api/_config.php` на сервере | нет |
| Токен Discogs, Jamendo | `darave_secrets.json` в `%LOCALAPPDATA%\DARAVE` | нет |
| Ключ Gemini | там же, или поле в интерфейсе DARAVE | нет |
| SSH-ключ для деплоя | Secrets репозитория на GitHub | нет |

`api/.htaccess` запрещает отдавать наружу всё, что начинается с
подчёркивания, — `_config.php` в том числе. `.gitignore` не пускает его
в репозиторий. Обе защиты уже стоят.

## Как положить секрет на сервер

Правило одно: **секрет должен попасть с вашего экрана в файл на сервере
напрямую**, без промежуточных остановок.

**Через панель** (проще). ispmanager → Менеджер файлов →
`www/darave.ru/api/` → `_config.php` → «Изменить». Вписать, сохранить,
закрыть.

**Через SSH** (быстрее, если уже в терминале):

```bash
ssh darave
nano ~/www/darave.ru/api/_config.php
```

Чего не делать:

* не копировать секрет в заметки, черновик письма или чат «чтобы не
  потерять» — там он и остаётся;
* не отправлять его мне, в поддержку хостинга или кому-либо ещё. Никому
  из них он не нужен: поддержка решает вопросы без ваших ключей, а я
  работаю с файлами, куда вы его впишете сами;
* не держать файл с ключом в папке проекта на своём компьютере — оттуда
  он рано или поздно уедет в git.

## Если секрет снова утёк

Не «наверное, обойдётся», а по шагам, в этом порядке:

1. **Выпустить новый.** Пока есть только старый, отзывать его страшно —
   сервис встанет.
2. **Вписать новый на сервер.**
3. **Отозвать старый.**
4. **Посмотреть журнал операций** — в кабинете ЮKassa видны все платежи
   и возвраты. Если появилось что-то чужое, писать в их поддержку сразу.

То же самое для пароля базы (панель хостинга → Базы данных →
Пользователи), токена Discogs и любого другого.

## Про деплой через GitHub Actions

Это следующий секрет, с которым вы столкнётесь, и он опаснее ключа
ЮKassa: **приватный SSH-ключ даёт полный доступ к хостингу.**

Правила те же, но с двумя добавками:

* Заводить **отдельный ключ только для деплоя**, а не тот, которым
  ходите сами:

  ```bash
  ssh-keygen -t ed25519 -C "github-deploy" -f ~/.ssh/darave_deploy
  ```

  Публичную половину (`darave_deploy.pub`) — в `~/.ssh/authorized_keys`
  на хостинге. Приватную — в **Settings → Secrets and variables →
  Actions** репозитория. После этого приватный файл с компьютера можно
  удалить: GitHub его больше не покажет, но и вам он не нужен.

* **`_config.php` не должен приезжать из репозитория.** Он лежит на
  сервере и переживает деплой. В скрипте выкладки его надо исключать —
  иначе однажды выложится версия из git с пустыми ключами, и оплата
  тихо перестанет работать:

  ```bash
  rsync -az --delete \
    --exclude '_config.php' \
    --exclude 'download/' \
    ./site/ darave:~/www/darave.ru/
  ```

  `download/` исключён отдельно: там 173 МБ установщика, которые незачем
  гонять при каждом пуше.

## Что делать прямо сейчас

1. Перевыпустить секретный ключ ЮKassa.
2. Вписать новый в `_config.php` на сервере.
3. Удалить файл `secret_key API yookassa.txt` у себя с диска.
4. Открыть `api/selftest.php?secret=…` — он скажет, приняла ли ЮKassa
   новый ключ, настоящим запросом к их API.
